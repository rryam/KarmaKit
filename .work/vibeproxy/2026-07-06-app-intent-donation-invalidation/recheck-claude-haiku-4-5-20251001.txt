**Critical issue found: gateFingerprint includes raw stableIdentifier and scopeID**

The `gateFingerprint` at CoreAgentApplePlatform.swift:3889-3900 includes:
- `subject.stableIdentifier` (e.g., "workflow:daily-review/outcome:completed")
- `subject.scopeID` (e.g., "workspace:coreagent")

These are then used in the consent request fingerprint at line 2111:
```swift
requestFingerprint: fingerprint(["app-intent-donation-record", record.gateFingerprint])
```

This means the consent request fingerprint **contains raw stable workflow IDs and scope IDs**, violating the requirement: *"consent request fingerprints should not contain raw stable workflow IDs or scope IDs."*

The test at line 1956-1957 only verifies that the request fingerprint doesn't directly contain the identifier strings, but when `gateFingerprint` itself embeds them, they appear in the final `requestFingerprint` passed to consent validation.

**Fix needed:** The `gateFingerprint` should hash the subject fields rather than including them raw:

```swift
var gateFingerprint: String {
  "sha256:" + sha256Hex(framed([
    donationIdentifier,
    descriptorIdentifier,
    descriptorExposureFingerprint,
    subject.kind.rawValue,
    // Hash these instead:
    "sha256:" + sha256Hex(subject.stableIdentifier),
    "sha256:" + sha256Hex(subject.scopeID),
    authorityBoundaryID,
    String(policyVersion),
  ]))
}
```
